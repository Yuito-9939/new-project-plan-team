## 1. 今週のタスクで登場した専門用語と解説

| 用語 | やさしい解説 |
|---|---|
| 【開発候補】タグ | 日次リサーチの中で「これはサービスとして開発できそうだ」とResearch部門が判断した情報に付ける目印。週次レポートではこのタグが付いた案件だけを取り出して評価する |
| 7軸評価 | 難易度・開発コスト・学習コスト・保守性・将来性・AIとの相性・初心者へのおすすめ度、の7つの物差しで案件を比較する方法。1つの物差しだけで「良い・悪い」を決めると見落としが出るため、複数の角度から見る |
| 経営企画の観点(収益モデル・採算) | 「そのサービスは実際にお金を生むか」を考える視点。収益モデル(どうやってお金をもらうか)、採算(黒字になるライン)、ROI(後述)などをセットで見る |
| 収益モデル | サービスがどうやってお金をもらうかの仕組み。今週出てきた「月額サブスク」は、毎月決まった金額を利用者から受け取る方式(例: 動画配信サービスの月額料金と同じ考え方) |
| ROI(投資利益率) | Return On Investment の略。「かけたお金(投資)に対して、どれだけ利益が出たか」を示す比率。例えるなら、10万円で仕入れた商品を15万円で売れたら、儲けは5万円＝ROIは50％、という考え方 |
| 損益分岐点・採算の目安 | 「売上と経費がちょうど同じになるライン」のこと。それより多く売れれば黒字、少なければ赤字になる。今週のレポートでは「月額2万円のサービスを、固定費15万円と仮定した場合、8人の有料ユーザーで黒字化する」という簡易計算を行った |
| 仮置き | 「本当の数値・根拠がまだ揃っていないが、話を進めるために仮の数値を置く」という意味。あとで実際のデータが取れたら必ず修正する前提の数値であることを明示するために使う |
| 一次情報 / 二次情報 | 一次情報は「調査を行った本人・組織が発表した元の情報」(例: 企業の公式発表、調査機関の元データ)。二次情報は「その一次情報を誰かがまとめ直した情報」(例: まとめサイトの紹介記事)。二次情報は伝言ゲームのように内容がずれることがあるため、重要な数値は一次情報での裏取りが望ましい |
| PoC(Proof of Concept) | 「概念実証」と訳される。本格的にお金と時間をかけて作る前に、小さく試して「本当にニーズがあるか・成立するか」を検証すること。今週のレポートでは「有料β版でPoCを行い、実際の支払い意欲データを取ってから本格投資を判断する」という提案をした |
| EGRESS_BLOCKED | AIが外部のWebサイトに情報を取りに行く(WebFetch)際、実行環境のネットワーク設定によりブロックされたことを示すエラー。今週の日次リサーチでは5日間このエラーが続き、一次情報への直接アクセスができない状態だった |

## 2. チームが行った判断と「なぜそう判断したか」

### 判断1: 経理・総務候補を「詳細評価しない」として一覧扱いにした
- **判断**: 「経理・総務のミニ常駐エージェント」は、週次レポートで候補Aのような詳細な表(7軸評価・経営企画の観点)を作らず、簡易な一覧行にとどめた。
- **なぜそう判断したか**: 08-18(水)にオーナーから「SNS候補を優先する」という指示があり、それ以降この候補の調査が止まっていたため。判断材料が先週(08-17)から更新されていない状態で無理に7軸評価や採算試算を作ると、根拠のない数値を書くことになりかねない。共通ルールの「未確認情報を事実として書かない」「分からないことは分からないと伝える」に従い、詳細評価を見送った。
- **学びのポイント**: 「材料が揃っていないものは、無理に評価を完成させない」という判断も、立派な意思決定の一つである。

### 判断2: 候補Aの推奨を「Go」でも「NoGo」でもなく「条件付き推奨」にした
- **判断**: 個人商店向けSNS集客半自動伴走サービス候補は、市場性・技術面は好材料が揃っているが、「条件付き推奨」(PoCでのデータ取得を条件とする)とした。
- **なぜそう判断したか**: 採算試算(月15万円の固定費、8人で黒字化)が、実際のデータに基づかない「仮置き」の数値だったため。良い兆候(成果不満層の厚さ)と、分からないこと(実際いくら払ってもらえるか)が両方あるときは、「全面的にGo」と言い切らず、「小さく試してから判断する」という中間的な提案をするのが、リスクを抑えた進め方になる。
- **学びのポイント**: ビジネス判断では「Yes/No」の二択だけでなく、「条件付きYes」という選択肢が有効な場面が多い。特にデータが不足している段階では、いきなり大きな投資をするより、小さく検証してから判断する方が失敗のコストを抑えられる。

### 判断3: 「飲食店68％が3ヶ月以内に更新停止」という数値を採用しなかった
- **判断**: 何度も検索に出てきた「68％」という数値を、最終的に週次レポートでは採用せず、「出典不明のため除外する方向」として扱った。
- **なぜそう判断したか**: 検索するたびに出典として挙げられる調査名が違っていたこと、原文サイトに直接アクセスしても403エラーで確認できなかったことから、「検索エンジンの要約が数値を生成してしまった可能性」を否定できなかったため。数字が具体的で説得力がありそうに見えても、出典を確認できない場合は使わない、というルールを徹底した。
- **学びのポイント**: 「もっともらしい数字」ほど、出典の確認を怠らないことが大切。特にAIによる検索結果の要約は、複数の情報が混ざって不正確な数値を作り出すことがあるため注意が必要。

## 3. 今週学んだことのまとめ(3〜5点)

1. 事業の「Go/NoGo判断」は、市場性・技術・採算の3つを別々に見たうえで、最後に総合して結論を出す。どれか1つが良くても、他が悪ければ安易にGoとは言えない。
2. 「仮置き」の数値を使うこと自体は悪いことではない。ただし、それを「仮の数値である」と明記し続けることが、後で正しい判断をするために重要である。
3. 一次情報にアクセスできない状況(EGRESS_BLOCKEDなど)が続いても、「今分かっている範囲でどこまで言えるか」を明確にしながら作業を進める姿勢が大切。
4. 「導入率が高い＝うまくいっている」とは限らない。今週のSNS集客調査では、「導入はしているが成果が出ていない」層が多いという発見が、事業アイデアのヒントとして最も価値があった。
5. データが足りない項目を無理に評価しない(経理候補の扱い)ことも、正確性を優先する上での正しい判断である。

## 4. 復習した方がよい内容

- ROI・損益分岐点の基本的な計算方法(今回は簡易計算だったが、固定費・変動費を分けて考える本格的な計算方法を復習すると理解が深まる)
- 一次情報と二次情報の違い、および出典を確認する具体的な手順(公式発表のURLを直接確認する、発表日・調査主体・回答者数をセットで見る、など)

## 5. 次に勉強すると良いこと(理由付き)

1. **簡易な損益計算(損益分岐点分析)の基礎**: 今回、固定費15万円・単価2万円という仮の数字で「8人で黒字化」という計算を行ったが、この考え方(固定費 ÷ 単価＝損益分岐点の人数)を自分で組み立てられるようになると、今後似た評価が来たときに数値の妥当性を自分でチェックできるようになる。
2. **PoC(概念実証)の設計方法**: 「小さく試してから判断する」という考え方は、今後もこのチームの意思決定で繰り返し出てくる。どんな規模で・どんな指標を見て・どのくらいの期間でPoCを行うべきかを学ぶと、Go判断が出たあとの動き方をイメージしやすくなる。
